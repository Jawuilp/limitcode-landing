# Posicionamiento de Limitcode

## Problema actual

La frase “AI coding agent for Sublime Text” explica la categoría, pero no explica suficientemente por qué alguien debería usar Limitcode en lugar de:

- Claude Code
- Codex CLI
- OpenCode
- Pi
- Cursor
- VS Code + Copilot
- TermMate + agentes CLI

Un usuario terminal-first puede responder:

> “Ya puedo abrir Claude/Codex/Pi en una terminal dentro de Sublime.”

Por eso hay que comunicar la diferencia de forma explícita.

---

## Propuesta de valor recomendada

### Versión corta

> **The lightweight AI coding agent built into Sublime Text.**

### Versión extendida

> **Stay in Sublime. Use a full coding agent without moving to a heavy AI IDE or adopting a terminal-first workflow.**

### Alternativa

> **Agentic coding for Sublime Text — lightweight, native, BYOK, and out of the way when you don't need it.**

---

## Los cuatro pilares

### 1. Lightweight

Limitcode debe apropiarse de la misma filosofía que hace atractivo a Sublime:

- rápido;
- ligero;
- simple;
- no intrusivo;
- sin necesidad de ejecutar un IDE AI completo.

No afirmar porcentajes de ahorro de RAM sin benchmarks.

Sí se puede afirmar:

- built to keep the Sublime workflow lightweight;
- no separate AI IDE required;
- direct API providers do not require a separate agent daemon;
- stays out of the way when not in use.

---

### 2. Native Sublime integration

No es “una CLI abierta dentro de Sublime”.

Debe comunicar:

- acceso a views;
- selección actual;
- archivos abiertos;
- edición directa;
- contexto del editor;
- sesiones;
- navegación;
- permisos;
- herramientas;
- futura revisión/diff integrada.

Mensaje:

> **The agent understands the editor you are already working in.**

---

### 3. Editor-first, not terminal-first

No atacar los agentes CLI.

La posición debe ser:

> Terminal agents are great if you want a terminal-first workflow. Limitcode is for developers who want the agent inside Sublime.

Eso evita una guerra innecesaria con Claude Code, Pi, Codex u OpenCode.

---

### 4. BYOK + multi-provider

Una interfaz común para:

- OpenAI
- Anthropic
- Gemini
- DeepSeek
- OpenRouter
- modelos locales
- otros endpoints compatibles

Beneficio:

> no cambiar de harness cada vez que cambias de modelo.

---

## Cliente ideal

### Muy buen fit

- usa Sublime actualmente;
- quiere seguir usando Sublime;
- quiere agentes modernos;
- no quiere cambiarse a Cursor/VS Code;
- no quiere vivir en terminal;
- valora bajo consumo;
- trabaja con hardware limitado o muchos procesos;
- usa varios proveedores/modelos;
- quiere una herramienta opcional.

### Fit medio

- usa Sublime + CLI agents;
- podría preferir una experiencia más integrada;
- le molesta gestionar varias herramientas.

### Mal fit

- terminal-first power user completamente satisfecho;
- ya dejó Sublime;
- no quiere IA;
- prefiere construir su propio harness;
- no le importa consumo de recursos.

---

## Importante: Limitcode no necesita reemplazar todo

No vender:

> “Abandona OpenCode/Claude Code.”

Vender:

> **Use Limitcode as your lightweight default agent inside Sublime, and reach for heavier terminal workflows only when you need them.**

Esto coincide mejor con un uso realista.

---

## Diferenciadores futuros a reforzar

- diff/review integrado;
- navegación visual de cambios;
- acciones sobre archivos;
- contexto explicado;
- “understand this project/file” mejorado;
- herramientas educativas/explicativas;
- skills;
- MCP;
- subagents;
- browser/tool integrations;
- debugging/test workflows.
