## Prioridad 2 — Nueva sección: Why not just use a terminal agent?

Crear una sección muy visible.

### Título

> **Why not just run Claude Code, Codex, Pi or OpenCode in a terminal?**

### Copy sugerido

> Terminal agents are excellent for terminal-first workflows. Limitcode is built for developers who want the agent to live where they already work: inside Sublime Text.

### Comparación

| Terminal-first workflow | Limitcode |
|---|---|
| Separate process/runtime | Runs as part of the Sublime workflow |
| Terminal-oriented interaction | Editor-oriented interaction |
| Context passed between tools | Uses editor context directly |
| Different harnesses/tools | One interface across providers |
| Review often happens elsewhere | Review can stay close to the editor |
| Great for terminal power users | Built for people who want to stay in Sublime |

No presentar esto como “Limitcode es mejor en todo”.

## Prioridad 3 — Sección Lightweight

### Título

> **Built to stay lightweight**

### Ideas

- Sublime is fast because it avoids unnecessary overhead.
- Limitcode follows the same philosophy.
- No separate AI IDE required.
- Direct API providers do not require a separate agent daemon.
- Keep your browser, dev server and tools running without turning the editor into the heaviest process on the machine.

### No incluir todavía

No poner:

- “70% less RAM”
- “faster than Claude Code”
- “uses less memory than OpenCode”

hasta tener pruebas reproducibles.
